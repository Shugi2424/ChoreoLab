# ChoreoLab — Deployment Guide

This guide covers deploying ChoreoLab to **MongoDB Atlas**, **Render** (API), and **Vercel** (client).

**Prerequisites:** CI passing on `master` (`npm test`, `npm run build`). See [TESTING.md](./TESTING.md).

---

## Overview

| Component | Platform | URL pattern |
| --------- | -------- | ----------- |
| Client    | Vercel   | `https://<project>.vercel.app` |
| API       | Render   | `https://<service>.onrender.com` |
| Database  | Atlas    | MongoDB connection string (private) |

The client talks to the API via `VITE_GRAPHQL_URL`. The API allows the client origin via `CORS_ORIGIN`.

### Dev vs production databases (recommended)

Use **one Atlas cluster** and **two database names** on the same connection string (same user/password/host):

| Environment | Where | Database name in URI |
| ----------- | ----- | -------------------- |
| Development | Local `server/.env` | `choreolab` |
| Production  | Render `MONGODB_URI` | `choreolab_prod` |

Example — only the path before `?` changes:

```
# Dev (local)
mongodb+srv://USER:PASS@CLUSTER.mongodb.net/choreolab?retryWrites=true&w=majority

# Prod (Render)
mongodb+srv://USER:PASS@CLUSTER.mongodb.net/choreolab_prod?retryWrites=true&w=majority
```

Atlas creates each database on first use. **Seed production once** (step 4) into `choreolab_prod`; leave your existing dev data in `choreolab` untouched.

## 1. MongoDB Atlas

If you already have a dev cluster, **reuse it** — add network access for Render and a **separate production database name** (see [Dev vs production databases](#dev-vs-production-databases-recommended) above).

1. Open your existing cluster at [cloud.mongodb.com](https://cloud.mongodb.com) (or create one — M0 free tier is fine).
2. **Database Access** — your existing user is fine (read/write on any database).
3. **Network Access** — add **`0.0.0.0/0`** if not already present (required for Render).
4. **Connect** → Drivers → copy the connection string and set the database name:
   - **Dev (local):** `...mongodb.net/choreolab?...`
   - **Prod (Render):** `...mongodb.net/choreolab_prod?...`
5. Keep the **production** URI for Render; keep **dev** URI in local `server/.env` only.

## 2. Render (GraphQL API)

### Option A — Blueprint (recommended)

1. Push this repo to GitHub.
2. In [Render](https://render.com) → **New** → **Blueprint**.
3. Connect the ChoreoLab repository. Render reads [`render.yaml`](../render.yaml).
4. Set **sync: false** env vars when prompted:
   - `MONGODB_URI` — Atlas connection string from step 1
   - `CORS_ORIGIN` — your Vercel URL (set after step 3, or update after first deploy)
   - `CLIENT_URL` — same Vercel URL (password reset links)
   - `RESEND_API_KEY` — from [resend.com](https://resend.com)
   - `EMAIL_FROM` — e.g. `ChoreoLab <noreply@yourdomain.com>` after domain verification
5. `JWT_SECRET` can be auto-generated by Render; do **not** use the dev default.

### Option B — Manual web service

| Setting | Value |
| ------- | ----- |
| Root directory | *(repo root)* |
| Build command | `npm ci --include=dev && npm run build:server` |
| Start command | `npm run start:server` |
| Health check path | `/health` |

**Environment variables:**

| Variable | Required | Example |
| -------- | -------- | ------- |
| `NODE_ENV` | yes | `production` |
| `MONGODB_URI` | yes | Atlas URI |
| `JWT_SECRET` | yes | long random string |
| `CORS_ORIGIN` | yes | `https://choreolab.vercel.app` |
| `CLIENT_URL` | yes | `https://choreolab.vercel.app` |
| `RESEND_API_KEY` | for email | Resend API key |
| `EMAIL_FROM` | for email | verified sender |
| `PORT` | no | Render sets automatically |

After deploy, verify:

```bash
curl https://YOUR-SERVICE.onrender.com/health
```

Expected: `{"status":"ok","service":"choreolab-api","db":"connected"}`

GraphQL endpoint: `https://YOUR-SERVICE.onrender.com/graphql`

## 3. Vercel (React client)

1. Import the GitHub repo in [Vercel](https://vercel.com).
2. **Root Directory:** `client`
3. **Framework Preset:** Vite
4. **Install Command:** `cd .. && npm ci`
5. **Build Command:** `cd .. && npm run build:client`
6. **Output Directory:** `dist` (relative to `client/`)

**Environment variable (Production + Preview):**

| Variable | Value |
| -------- | ----- |
| `VITE_GRAPHQL_URL` | `https://YOUR-SERVICE.onrender.com/graphql` |

[`client/vercel.json`](../client/vercel.json) enables SPA routing (React Router).

### Custom domain (optional)

1. Vercel → Project → **Domains** → add your domain.
2. Update Render `CORS_ORIGIN` and `CLIENT_URL` to the custom domain.
3. Redeploy Render (env change triggers restart).

## 4. Seed production reference data

Reference data (body elements, bases, requirements, etc.) must exist before coaches can build routines.

From your **local machine** (with network access to Atlas):

```bash
cd server
cp .env.example .env
# Edit .env — set MONGODB_URI to the **production** Atlas URI
npm run seed
```

Ensure your IP is allowed in Atlas **Network Access** for the seed run.

The seed is **idempotent** — safe to re-run; it upserts reference collections and removes stale entries.

---

## 5. Wire CORS after first Vercel deploy

1. Deploy Vercel → note the URL (e.g. `https://choreolab.vercel.app`).
2. In Render → Environment → set:
   - `CORS_ORIGIN=https://choreolab.vercel.app`
   - `CLIENT_URL=https://choreolab.vercel.app`
3. Render redeploys automatically.

If CORS is wrong, the browser shows network errors on GraphQL requests from the client.

## 6. Post-deploy smoke checklist

Run manually on production URLs ([ROADMAP.md](./ROADMAP.md#post-deploy-smoke-checklist-manual)):

- [ ] `GET /health` returns `status: ok` and `db: connected`
- [ ] Sign up → log in → `me` query works
- [ ] Forgot password → email received (if Resend configured)
- [ ] Create routine → add body element, risk, mastery, artistry
- [ ] DB/DA scores and validation update after timeline changes
- [ ] My Routines list → open → delete

Phone QA: optional repeat of [TESTING.md § Manual phone QA](./TESTING.md#manual-phone-qa-m9) against the Vercel URL.

## Local production build (sanity check)

```bash
npm ci
npm run build:server   # shared + server → server/dist
npm run build:client   # shared + client → client/dist
```

Start API locally against Atlas (or local Mongo):

```bash
cd server
# .env with NODE_ENV=production, CORS_ORIGIN, CLIENT_URL, etc.
npm start
```

## Troubleshooting

| Symptom | Likely cause |
| ------- | ------------- |
| Health `503`, `db: disconnected` | Wrong `MONGODB_URI` or Atlas IP block |
| CORS error in browser | `CORS_ORIGIN` does not match Vercel URL exactly (no trailing slash) |
| GraphQL network error on client | Wrong `VITE_GRAPHQL_URL` or Render service sleeping (free tier) |
| Empty inventory / validation errors | Production DB not seeded — run `npm run seed` |
| Password reset email missing | `RESEND_API_KEY` unset or unverified `EMAIL_FROM` |
| Server won't start in production | Default `JWT_SECRET` or missing `CORS_ORIGIN` / `CLIENT_URL` |
